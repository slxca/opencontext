## OpenContext Workflow

OpenContext stores durable project memory as markdown files in `.opencontext/`. Check it before and after structural work.

- Before making structural code changes, run `read_context` to inspect existing project topics and architectural decisions.
- Whenever a new architectural convention, database schema, or API rule is established or refactored, call `save_context` with a concise, topic-scoped markdown summary. Use YAML frontmatter (`status`, `supersedes`) when updating conventions to track lifecycle changes.
- When a topic becomes obsolete, call `delete_context` to remove it. For deprecated topics that should remain visible, set `status: deprecated` or `status: superseded` in the frontmatter instead of deleting.

## Repository

pnpm monorepo (pnpm@9.15.4). Two packages:
- `packages/opencontext` — the `opencontext-mcp` MCP server (published npm package, the real product).
- `apps/web` — private Next.js marketing/docs site (`@opencontext/web`).

Run everything from the repo root with pnpm. Never use `npm` — `apps/web` has a stale npm `package-lock.json` and its own `node_modules`.

## Commands

```bash
pnpm install          # install workspace deps (CI uses --frozen-lockfile)
pnpm build            # pnpm -r build
pnpm typecheck        # pnpm -r typecheck
pnpm test             # pnpm -r test — only runs in packages that define test (web has none)
pnpm dev              # pnpm -r --parallel dev — currently only starts the web dev server
```

- There is no root `lint` script. Lint only exists in `apps/web`: `pnpm -F @opencontext/web lint`.
- CI (`.github/workflows/ci.yml`, Node 22, branch `master`) runs: package typecheck/build/test; web typecheck/build/lint. Match that before pushing.

## packages/opencontext (opencontext-mcp)

- Entry: `src/index.ts`. Source is split into domains (`cli/`, `server/`, `config/`, `store/`, `validation/`, `init/`, `shared/`); each folder's `index.ts` is its public surface.
- TypeScript `NodeNext` — all relative imports must use the `.js` extension (e.g. `from "./server/index.js"`). Omitting it breaks the build.
- Build is `tsc -p tsconfig.json && chmod +x dist/index.js` — the chmod is required for the `opencontext-mcp` bin.
- Strict TS: `noUncheckedIndexedAccess` and `exactOptionalPropertyTypes` are on; expect null-checking and explicit-optional handling.
- Tests: Vitest, files in `test/**/*.test.ts`. Run one file from the package dir: `pnpm exec vitest run test/<file>.test.ts`. Tests use real temp dirs under `os.tmpdir()`, no fixtures dir.
- CLI subcommands: `server` (default), `init`, `help`, `version`. `init` takes no args, is interactive-only, and never overwrites existing config.
- Config is plain JSON (`.opencontext.json`); no JSONC/comments/trailing commas anywhere.
- Running the server prints a banner to stderr unless `OPENCONTEXT_TELEMETRY_DISABLED=1` or `DO_NOT_TRACK=1`.

## OpenContext data files

- `.opencontext/index.md` is auto-generated by the store — never edit it manually.
- `.opencontext.json` enables `autoIndex` and write guards (`guard.maxFileSizeKb`, `strictPatternCheck`).
- The `<!-- OPENCONTEXT:START/END -->` section in this file (and `CLAUDE.md`) is auto-managed by `init`; keep content outside the markers.
- `.opencontext/codebase-structure.md` holds an existing context topic describing the package layout — read it via `read_context` before restructuring.
